# OpenTypeless 开发完成后的审查、修复与验收流程

本文定义 Kimi K3 完成开发后，由 Codex 执行的独立审查流程。审查目标不是确认“界面能打开”，而是验证应用在真实 Apple 芯片 Mac 上长期使用时不会丢失录音、泄露密钥、破坏历史数据或在关键输入场景中失效。

## 一、角色与责任

### Kimi K3

- 按 `tasklist.md` 实现并在 `todolist.md` 留下可复现验证证据。
- 提交完整代码、迁移、测试、构建说明和已知限制。
- 不得把占位功能、关闭的测试或手工绕过描述为完成。
- 收到缺陷后完成根因修复、回归测试和缺陷关闭说明。

### Codex

- 独立阅读需求、架构和代码，不以 Kimi 的完成声明替代验证。
- 执行静态审查、自动化测试、构建和真实 Mac 测试。
- 给缺陷分级，提供文件、行号、复现步骤、实际/预期结果和建议验证范围。
- 严重和高优先级缺陷必须退回 Kimi 修复；修复后重新审查受影响模块和相邻风险区域。

### 用户

- 决定是否接受明确列出的中低优先级限制。
- 批准需求变更、范围削减或会导致用户数据格式不兼容的修改。

## 二、进入审查的前置条件

只有同时满足以下条件才能开始正式审查：

- `tasklist.md` 中计划发布的任务均满足验收标准。
- `todolist.md` 没有未说明的进行中任务，且每项完成任务都有验证证据。
- 工作树没有来源不明的生成文件、密钥、录音样本或个人数据。
- 格式化、静态检查、类型检查、单元测试、集成测试和生产构建均通过。
- 数据库迁移可从空库执行，并有至少一条旧版本升级路径测试。
- 提供 Apple 芯片 `.app` 和 `.dmg`，或提供一条可复现的本地构建命令。
- 提供已知缺陷、未实现范围和人工测试清单。

缺少上述材料时，Codex 先记录“审查准备不完整”，不替开发者补写虚假证据。

## 三、审查顺序

建议按以下顺序执行，以便尽早发现会使后续测试无意义的问题：

1. 需求追踪和仓库卫生。
2. 架构与依赖边界。
3. 数据库迁移和录音耐久性。
4. 密钥、日志和网络安全。
5. 模型适配器契约。
6. macOS 权限与 AppKit 平台集成。
7. SwiftUI 功能、可访问性和 Liquid Glass 视觉一致性。
8. 自动化测试与生产构建。
9. 真实 Apple 芯片 Mac 端到端测试。
10. 缺陷修复、回归和最终发布判定。

## 四、静态代码审查清单

### 4.1 需求完整性

- 登录、注册、会员、订阅、邀请码、额度、广告和云同步是否完全不存在。
- 今日、当周、累计统计口径是否符合中英文混合计数规则。
- 历史是否支持任意日期、搜索、状态、收藏、复制、下载、删除和重试。
- 所有成功和失败录音是否默认永久保留。
- 转录失败、改写失败和自动输入失败是否分别处理。
- 词典是否为单词级手动维护，并正确进入模型请求能力范围。
- 自动输入是否默认开启，并有失败后的可恢复路径。

### 4.2 架构一致性

- 主界面使用 SwiftUI，系统集成仅在必要处使用 AppKit/Apple 原生框架；不存在 Vue、React、Tauri、Electron、Rust 或 WebView 主界面。
- SwiftUI 视图只负责界面和交互，不持有完整密钥，不承担录音耐久性和协议拼装。
- 共享 Swift 业务核心、Apple 平台能力协议和 macOS 实现之间边界清晰。
- 厂商协议逻辑是否收敛在适配器，不散落于页面、录音或历史模块。
- 业务核心是否避免直接依赖 AppKit/macOS 专用类型，以支持未来 iPhone/iPad 复用。
- AVFoundation、URLSession、GRDB/SQLite 与 Swift Package 的使用是否符合架构约定，第三方依赖是否经过必要性和许可证审查。
- Swift Concurrency 隔离是否明确：可变共享状态由 actor 或同等机制保护，UI 更新在 `MainActor`，取消和生命周期正确传播。
- 统一错误模型、状态机和数据仓储是否为唯一可信实现，是否存在重复状态源。
- 是否存在巨型模块、循环依赖、隐式全局状态、无界队列或无法取消的后台任务。
- 依赖是否必要、维护活跃、许可证可接受；是否引入来源不明的二进制。

### 4.3 代码可靠性

- 检查强制解包 `!`、`try!`、`fatalError`、`preconditionFailure`、忽略错误、无界 `Task`、滥用 `@unchecked Sendable` 和 `nonisolated(unsafe)`。
- 网络请求是否有连接、读取和总超时，重试是否有上限和退避。
- 文件和数据库操作是否处理并发、重复点击、重复事件和应用退出。
- 是否避免在异步执行器中阻塞录音或界面线程。
- 所有资源是否有明确生命周期：AVAudioEngine/录音器、输入设备观察、文件句柄、URLSession WebSocket、Task、窗口和菜单栏项；不得把 iOS 专属音频会话 API 错用于 macOS。
- 删除和覆盖操作是否校验路径，防止目录穿越、误删数据根目录或跟随危险符号链接。

## 五、安全与隐私审查

当前版本允许密钥存入本地 SQLite，但必须满足最低门禁：

- 数据库及其父目录仅当前用户可访问。
- SwiftUI 状态、日志、错误、通知、遥测、测试快照和导出中无完整密钥。
- 模型配置查询默认返回掩码；更新密钥时不会因空掩码覆盖真实值。
- `Authorization`、`x-api-key`、自定义鉴权头和 URL 查询参数均被脱敏。
- Git 历史、构建脚本、示例配置和测试夹具中无真实密钥。
- 应用不存在未声明的遥测、崩溃上传、更新检查或后台上传。
- 音频和文字只发送到用户主动启用的模型端点。
- 自定义基础地址需防止明显危险配置；至少记录本地/明文 HTTP 风险并避免把密钥发送到非预期重定向目标。
- 整库备份明确提示包含密钥；普通历史导出不包含模型配置和密钥。
- 日志默认不保存完整口述文字和音频内容。

发现任何真实密钥进入 Git 历史，按严重缺陷处理：立即停止审查、吊销密钥、清理历史并重新审查。

## 六、数据库迁移审查

必须验证：

- 全新空数据库可创建到最新版本。
- 每个已发布旧版本可按顺序升级到最新版本。
- 重复启动不会重复执行或破坏迁移。
- 迁移中断后能安全回滚或在下一次启动继续处理。
- 时间以 UTC 保存，本地显示正确；跨日和周起始边界统计正确。
- 外键、唯一约束、状态约束和索引与查询需求一致。
- 模型配置删除后，历史记录仍保留必要的模型快照，不产生悬空引用。
- 录音资源与口述记录的关联在删除、重试、恢复和迁移后保持一致。
- 相对路径或资源标识能够在移动数据根目录后解析。
- 大量历史数据下分页、搜索、统计和启动时间可接受。

至少构造以下数据集：空库、单条成功、各种失败状态、跨时区/跨周、中英混合、收藏、已删除模型配置、遗留未完成录音、数万条历史记录。

## 七、录音耐久与恢复审查

这是发布阻断级核心能力。必须验证：

- 开始录音后音频持续落盘，而非只存在内存。
- 正常停止后文件可播放、时长合理、格式可被适配器接受。
- 录音中强制退出、进程崩溃、电脑休眠、麦克风断开、权限被撤销后，已有数据不会静默丢失。
- 下次启动可发现未完成记录，并将可用音频转换为明确的可重试状态。
- 转录网络失败、认证失败、限流、超时、响应损坏时原音频仍存在。
- 改写失败不会触发重复录音或强制重新转录。
- 自动输入失败不会将已完成文本标为转录失败。
- 成功录音永久保留，重试不得覆盖或删除原始文件。
- 下载内容与历史记录所引用文件一致。
- 删除需确认，且数据库/文件不一致时有修复或诊断机制。
- 磁盘空间不足、只读目录和文件写入失败必须在录音早期明确提示。

建议使用故障注入测试文件写入失败、数据库提交失败、模型超时和应用异常退出，而不是只靠手动断网。

## 八、模型适配器审查

### 8.1 语音识别

OpenAI 兼容适配器必须通过本地模拟服务验证：

- 基础地址与端点拼接无重复路径或丢失路径。
- 文件表单、模型、语言、提示词和自定义头正确。
- 鉴权、超时、限流、服务端错误和解析错误被标准化。
- 重定向不会把密钥泄露到非预期主机。
- 错误文本和调试日志经过脱敏。
- 连接测试不产生历史记录和统计。
- 中英混合、长音频、空音频和不支持格式行为明确。

适配器注册机制应能新增千问、豆包实现而无需修改录音状态机、历史服务和页面核心逻辑。未实现的协议不得显示为可正常使用。

### 8.2 文字改写

分别对 OpenAI 和 Anthropic 兼容适配器验证：

- 请求头、消息结构、模型名和响应解析正确。
- 关闭改写时完全跳过网络请求，原始转录成为最终文字。
- 原始和最终文字均保存。
- 超时、认证、限流、空响应和格式异常可重试且不丢数据。
- 提示词保护原意、数字、代码、专有名词和中英混合，不凭空补充事实。
- 仅重试改写不会增加语音转录请求次数。

## 九、macOS 平台与权限审查

在全新权限状态和已授权状态分别测试：

- 麦克风权限说明、请求、拒绝、再次引导和系统设置跳转。
- 辅助功能权限说明、请求、拒绝、授权后恢复。
- 全局快捷键注册、冲突、重复触发、按一次开始/再按一次停止。
- 快捷键在主窗口关闭、菜单栏运行和其他应用前台时工作。
- 向常见应用输入：文本编辑、浏览器、聊天工具、代码编辑器、终端安全输入场景。
- 自动输入前后剪贴板内容尽可能恢复；图片、多格式剪贴板不能被无声破坏。
- 密码框、安全输入和不允许辅助输入的场景不应卡死或丢失文字。
- 切换麦克风、插拔音频设备、休眠唤醒后可以继续录音。
- 开机启动、程序坞显示、托盘和窗口生命周期符合设置。
- Apple 芯片生产构建架构正确，没有依赖未声明的 Rosetta。
- 应用升级后权限、数据目录和历史记录不丢失。

## 十、SwiftUI 与视觉审查

视觉基线是“像 Apple 平台原生系统工具，并正确使用 Apple 原生 Liquid Glass”；审查时必须逐条对照根目录 `DESIGN.md`：

- 使用系统语义颜色、系统字体、SF Symbols 和原生控件层级；强调色跟随系统设置。
- 统一设计令牌只补充系统没有表达的产品状态，不覆盖系统控件尺寸和平台行为。
- 系统支持时，Liquid Glass 必须通过 Apple 原生 SwiftUI/AppKit API 实现，并具有正确的编译期/运行时可用性检查；禁止自制模糊着色器、截图纹理或 Web/CSS 仿制。
- 玻璃效果只出现在导航、工具栏、录音胶囊、菜单和临时浮层等控制层；长列表、正文、设置表单和大面积背景必须保持稳定可读。
- 旧 macOS 必须使用系统 Material、原生视觉效果或清晰的不透明层级降级，且功能、对比度和点击区域不能缩水。
- 开启“减少透明度”时不依赖透明玻璃表达边界；开启“减少动态效果”时关闭非必要缩放、弹跳、波纹和连续动画。
- SwiftUI 与 AppKit 桥接控件必须在系统外观、深浅色、强调色、键盘焦点和辅助功能上表现一致。
- 大标题和留白不应牺牲信息可读性；窗口缩小时不能遮挡关键操作。
- 首页、历史、词典、设置和悬浮条保持一致的层级与交互语言。
- 不出现 Typeless 商标、Logo、专有图片、订阅文案或像素级复制。
- 失败状态明确但不过度铺红，重试/下载/删除操作可理解。
- 空、加载、失败、权限不足、模型未配置、离线、大数据量状态完整。
- 所有操作可通过键盘到达；可见焦点明确；颜色对比和点击区域合理。
- 不依赖鼠标悬停才能访问唯一关键操作。
- 所有用户文案进入 String Catalog；没有散落的不可本地化硬编码中文。
- 动效尊重系统“减少动态效果”设置，悬浮层不抢焦点、不遮挡主要工作。

审查时应对照产品设计文档和用户提供的参考图，而不是只凭开发者自述。

## 十一、自动化与端到端验证

Codex 应先读取仓库定义的命令，再运行等价于以下门禁：

```text
Swift 格式检查
Swift 静态检查（警告按项目门禁处理）
Swift Package 解析与单元测试
应用单元与集成测试
GRDB/SQLite 数据库迁移测试
URLSession 模型适配器契约测试
XCUITest 端到端与可访问性测试
xcodebuild Apple 芯片 Release 构建与归档
.app 与 .dmg 安装包构建
```

核心端到端场景至少覆盖：

1. 首次启动、权限引导、模型配置。
2. 快捷键录音、停止、转录、改写、自动输入和历史保存。
3. 不启用改写时的直接输入。
4. 转录失败后保留音频并重试成功。
5. 改写失败后只重试改写。
6. 自动输入失败后从历史复制。
7. 收藏、查询、复制、下载和删除。
8. 应用异常退出后的录音恢复。
9. 重启后统计、模型配置和历史一致。
10. 无真实密钥的模拟服务完整流程。

自动化通过不替代真实 Mac 测试；真实 Mac 测试也不替代可重复的自动化测试。

## 十二、真实 Apple 芯片 Mac 验收矩阵

每次候选发布至少记录：

- 机器型号与芯片。
- macOS 版本。
- 应用版本、提交号和构建校验值。
- 首次安装与覆盖升级结果。
- 麦克风和辅助功能权限结果。
- 至少两个麦克风输入设备（如有条件）。
- 至少五类目标输入应用。
- 中文、英文和中英混合录音。
- 短录音、较长录音、静音和噪声场景。
- 离线、超时、认证失败、限流和服务端错误。
- 强制退出、休眠唤醒、磁盘空间异常。
- `.dmg` 安装、移动到“应用程序”、首次运行和卸载后的数据处理说明。
- 系统支持 Liquid Glass 与不支持 Liquid Glass 的 macOS 版本各至少一组视觉验证；若测试设备不足，旧系统至少通过受支持运行环境和截图证据验证。
- 浅色、深色、提高对比度、减少透明度、减少动态效果、不同系统强调色。
- 常规窗口、最小支持窗口、较大窗口和多显示器/不同缩放比例。
- SwiftUI/AppKit 混合窗口的焦点、菜单、键盘导航、旁白辅助功能和录音胶囊层级。
- 如仓库已经包含共享 iOS/iPadOS Swift Package：在不开发移动端产品的前提下，至少验证共享包能为对应 Apple 平台编译，且不意外依赖 AppKit；不要求首版生成 iPhone/iPad 应用。

测试记录必须包含预期、实际结果和证据路径。不得只写“测试正常”。

## 十三、缺陷严重级别

等级与任务优先级映射为：严重级 = P0，高优先级 = P1，中优先级 = P2，低优先级 = P3。P0/P1 必须清零才能发布。

### 严重级

满足任一条件：

- 录音、历史或用户数据静默丢失/损坏。
- 密钥或完整隐私数据泄露到日志、SwiftUI 状态、Git 或非预期端点。
- 删除了范围外文件，或存在可利用的路径/命令执行漏洞。
- 应用无法启动、无法录音，或核心闭环在支持的 Mac 上普遍不可用。
- 数据库迁移破坏已有数据且无法恢复。

处理：立即停止发布，必须由 Kimi 修复并补充防回归测试；Codex 对根因和相邻模块重新完整审查。

### 高优先级

满足任一条件：

- 核心功能在常见场景失败，但有手工绕过方式。
- 转录/改写失败不能正确重试，或成功/失败录音未永久保留。
- 自动输入、快捷键、权限或剪贴板在常见应用中不可靠。
- OpenAI 语音、OpenAI 改写或 Anthropic 改写协议不符合约定。
- 统计、历史、收藏、删除或模型配置产生明显错误。
- 生产构建、安装包或升级路径失败。

处理：不得发布。必须由 Kimi 修复、更新 `todolist.md`、补测试并提交 Codex 复审。

### 中优先级

- 非核心场景行为不正确、错误信息不清楚、明显可访问性问题。
- 性能退化但不导致数据丢失。
- 视觉与设计系统明显不一致。
- 存在可维护性风险，但当前功能正确。

处理：默认应由 Kimi 在发布前修复。只有用户明确接受且有临时缓解措施、跟踪编号和后续计划时，才可延期。

### 低优先级

- 轻微视觉、文案、边缘交互或不影响使用的代码清理问题。

处理：可进入后续任务，但必须登记，不得从审查报告中消失。

## 十四、何时必须退回 Kimi 修复

以下任一情况都必须让 Kimi 修复后再审，Codex 不应直接代替开发者大范围重写并宣布通过：

- 存在任何严重级或高优先级缺陷。
- 核心验收场景没有测试或验证证据。
- 迁移、录音恢复、密钥脱敏或模型契约测试缺失。
- 为通过测试而删除、跳过或放宽测试。
- 实现偏离已确认产品范围，加入登录、订阅、云同步或其他未授权能力。
- 公共架构边界被破坏，使后续平台扩展必须重写核心业务。
- 生产构建或真实 Mac 核心闭环尚未通过。
- `todolist.md` 状态与实际代码、测试或已知缺陷不一致。

Codex 可以直接修复仅限于：低风险文档错误、审查脚本小问题、用户明确要求的紧急小修。任何涉及状态机、数据库迁移、录音、密钥、协议或平台权限的实质修复，原则上退回 Kimi，以确保原开发者同时补齐设计解释和回归测试。

## 十五、复审要求

Kimi 修复缺陷时必须提供：

- 缺陷编号和根因。
- 修改文件和行为变化。
- 新增或更新的回归测试。
- 本地验证命令和结果。
- 数据迁移或兼容性影响。
- 未解决风险。

Codex 复审时不能只检查差异行，至少要：

- 重跑缺陷复现步骤。
- 重跑新增回归测试和受影响测试集。
- 审查相邻状态和错误路径。
- 对严重级问题重新运行完整发布门禁。
- 确认 `todolist.md` 与缺陷状态同步。

同类问题连续两次修复失败时，应暂停补丁式修改，要求 Kimi 提供根因分析和更小、可验证的重构方案。

## 十六、最终发布判定

只有满足以下全部条件，Codex 才能建议用户接受候选版本：

- 无严重级和高优先级未解决缺陷。
- 中优先级缺陷已修复，或由用户书面接受并登记缓解措施。
- 自动化门禁全部通过，无跳过的核心测试。
- 真实 Apple 芯片 Mac 核心闭环通过。
- 空库初始化、升级迁移、异常恢复和永久录音保留通过。
- OpenAI 语音、OpenAI 改写、Anthropic 改写契约通过。
- 密钥脱敏、数据导出和日志安全通过。
- Swift Package 依赖可复现解析，`.app`、归档和 `.dmg` 可复现构建并记录校验值。
- 文档、`tasklist.md`、`todolist.md` 和实际实现一致。
- 已知限制完整披露。

最终审查报告应包含：结论、版本与提交号、执行的命令、测试环境、通过项、缺陷清单、残余风险、是否建议安装，以及若不通过应退回 Kimi 的明确任务列表。
