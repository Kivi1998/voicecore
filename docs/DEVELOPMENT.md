# VoiceCore 开发与交付指南

## 1. 产品范围

VoiceCore 是一款本地优先的 Apple Silicon macOS 语音输入工具。首版核心闭环：

1. 用户按一次全局快捷键开始录音。
2. 用户再次按相同快捷键结束录音。
3. 应用先完整、永久保存录音。
4. 应用调用用户配置的语音识别服务。
5. 可选调用文字改写服务。
6. 应用保存原始和最终文字。
7. 应用默认将最终文字写入当前输入框。
8. 所有记录可搜索、复制、下载、收藏、删除和按失败阶段重试。

不在首版范围：登录、会员、订阅、内置额度、遥测、云同步、Windows、iPhone、iPad、Android、团队功能和自动学习词典。

## 2. 开发约束

- 界面使用 SwiftUI；macOS 专属窗口、菜单栏、全局快捷键、辅助功能和剪贴板使用 AppKit。
- 录音和播放使用 AVFoundation，网络使用 URLSession，持久化使用 GRDB + SQLite。
- 项目使用 Swift Package Manager 按领域、应用服务、数据、音频、模型适配和平台能力模块化。
- SQLite 明文保存 API 密钥，后续再设计加密；当前仍不得把密钥暴露到日志或 SwiftUI 可观察状态。
- 所有录音永久保存，除非用户明确删除。
- 所有网络请求都发生在录音安全落盘之后，实时协议也必须同步写盘。
- 无服务端，不依赖 FastAPI 或常驻 Python 进程。
- 第一版仅发布 Apple Silicon macOS 应用，不生成 Intel 架构切片。
- 实现应遵循 `ARCHITECTURE.md`、`DATA_MODEL.md` 和 `PROVIDER_PROTOCOLS.md`。

## 3. 本地开发环境

开发机需要：

- Apple Silicon Mac。
- 当前稳定版 Xcode 和 Command Line Tools。
- 项目指定的 Swift 工具链和 macOS SDK。
- Xcode 项目启用 Swift 严格并发检查；新代码满足 `Sendable` 与 Actor 隔离要求。
- Apple Developer 签名与公证身份仅在正式发布环境需要。
- SwiftFormat、SwiftLint 等工具应锁定版本，并通过统一脚本安装或执行。

仓库根 `Makefile` 是唯一命令入口：

```sh
make resolve
make dev
make format-check
make lint
make test-packages
make test-app
make e2e
make mock-smoke
make archive
make dmg
```

`make archive` 生成 `build/VoiceCore.xcarchive`；`make dmg` 从归档内应用生成 `build/VoiceCore.dmg`。本地候选采用临时签名，公开发布前仍须 Developer ID 签名、公证和干净账户验收。README 只引用该入口，禁止维护多套互相冲突的命令。

## 4. 开发顺序

### 4.1 基础阶段

- 初始化原生 macOS App、Xcode 工程和 Swift Package 模块。
- 建立格式化、静态检查、测试和构建命令。
- 建立 String Catalog，所有首版中文文案进入 `.xcstrings` 资源。
- 建立 Swift 领域错误、用户错误和脱敏诊断错误体系。
- 实现数据目录定位、SQLite 连接、迁移和仓储测试。
- 建立应用服务、SwiftUI 可观察模型和平台服务协议的调用约定。
- 建立 AppKit 生命周期适配、菜单栏入口和依赖组合根，但暂不混入业务实现。

### 4.2 核心闭环阶段

- 实现权限状态检测与引导。
- 使用 AVFoundation 实现麦克风枚举、录音、持续写盘、播放和文件校验。
- 使用 AppKit / Core Graphics 实现全局快捷键和单会话串行控制。
- 实现口述状态机和异常启动恢复。
- 实现 OpenAI 音频转录适配器。
- 实现 OpenAI 与 Anthropic 改写适配器。
- 使用 AppKit 剪贴板和辅助功能事件实现 macOS 文字注入和剪贴板恢复。
- 完成从快捷键到当前输入框的真实闭环。

### 4.3 产品界面阶段

- 首页统计和最近记录。
- 历史记录查询、筛选、搜索和分页。
- 失败重试、仅重新改写、复制、下载、收藏、删除。
- 词典添加、搜索和删除。
- 模型配置、连接测试、快捷键、麦克风和常规设置。
- 菜单栏菜单和录音状态浮层。

### 4.4 稳定与发布阶段

- 中英混合、断网、限流、崩溃恢复和长录音测试。
- 权限首次授权、拒绝和撤销测试。
- 多种目标应用自动输入测试。
- 数据库升级和应用覆盖安装测试。
- Apple Silicon 签名、固化、公证及 DMG 构建。
- 最终隐私、日志和依赖许可证审查。

## 5. 模块完成定义

一个模块只有同时满足以下条件才算完成：

- 有清晰接口和错误定义。
- 有成功、失败和边界情况单元测试。
- 不输出密钥、完整音频或口述文本到日志。
- 用户可见错误包含可执行建议。
- 对数据库和文件产生的状态可恢复。
- 文档与实现一致。
- 格式化、静态检查、测试和生产构建全部通过。
- 至少完成一次真实 macOS 人工验收。

## 6. SwiftUI 开发规范

- View 不得直接调用 AppKit、AVFoundation、GRDB 或供应商 API；统一通过依赖注入的应用服务和可观察模型。
- 可观察模型只缓存展示状态，刷新时以应用服务和仓储查询为准。
- 所有修改界面状态的类型和方法明确运行于 `@MainActor`。
- View 保持轻量；导航、异步动作和业务判断放入 Feature Model 或应用服务。
- 组件应覆盖加载、空数据、成功、失败、禁用和权限不足状态。
- 历史记录使用稳定分页，避免全量加载。
- 所有危险操作均需明确确认，删除录音说明不可恢复。
- 设置中的密钥输入框只展示遮罩，不把完整密钥放进长生命周期可观察对象。
- 所有界面实现先对照根目录 `DESIGN.md`，优先使用系统语义字体、颜色、SF Symbols、间距和原生控件。
- Liquid Glass 只通过系统 SwiftUI/AppKit API 实现，并提供 macOS 14 原生材质降级；不自绘网页式玻璃。
- 不使用第三方产品商标、品牌素材、原始截图资源或像素级布局。
- 交互不能依赖鼠标悬停；所有核心操作必须可通过点击和键盘访问。
- 基础无障碍要求：明确焦点态、语义标签、足够对比度和可操作热区。
- 所有时间通过 `FormatStyle` 和本地化资源展示，不能在 View 中手工拼接。

## 7. Swift 核心与平台开发规范

- 领域状态机和协议接口只依赖 Foundation；不得依赖 SwiftUI、AppKit、AVFoundation 或 GRDB。
- AppKit 桥接对象只做系统事件转换、权限调用和平台实现，不承载业务状态机。
- 数据库事务不得跨越网络请求。
- 录音文件采用流式写入，不在内存保留完整长录音。
- 后台任务使用结构化并发，必须支持取消并有明确所有权；禁止无主 `Task.detached`。
- 可变会话状态封装在 Actor 中，避免快捷键、界面操作和网络回调产生数据竞争。
- 每个供应商适配器只处理本协议，不直接更新历史记录。
- macOS 系统调用位于平台模块，并通过 Swift protocol 暴露。
- 对外错误分为用户消息与内部诊断，前者脱敏，后者也不得包含秘密。
- 禁止强制解包处理正常运行时可遇到的输入、文件、网络和权限错误。

## 8. 应用服务接口

SwiftUI Feature Model 只调用稳定的应用服务方法，至少包括：

- `getAppState()`
- `startRecording()`
- `stopRecording()`
- `cancelRecording()`
- `listRecords(query:)`
- `getRecord(id:)`
- `retryTranscription(id:)`
- `retryRewrite(id:)`
- `copyRecordText(id:)`
- `injectRecordText(id:)`
- `downloadAudio(id:to:)`
- `toggleFavorite(id:)`
- `deleteRecord(id:)`
- `getStatistics(range:)`
- 词典增删查命令
- 提供商配置增删改查、设为默认和测试连接命令
- 设置读写、设备枚举和权限状态命令

应用服务通过 `AsyncStream`、Observation 或 Combine 发布录音级别、时长、状态变化、权限变化和全局错误。事件中不得包含 API 密钥；长文字应按需查询，不要在高频事件重复传输。

应用服务输入输出使用领域值对象，禁止以松散字典在模块之间传递。跨 Actor 传递的实体和错误应满足 `Sendable`。

## 9. 测试策略

### 9.1 单元测试

- 状态机允许和禁止的转移。
- 中英文混合统计规则。
- URL 拼接、请求构造和响应解析。
- 错误归一化和脱敏。
- 数据库仓储、筛选、分页和迁移。
- 录音路径生成和文件恢复判断。
- SwiftUI Feature Model、格式化器和关键 View 状态。

### 9.2 集成测试

- 使用临时目录和真实 SQLite 文件运行仓储与恢复流程。
- 使用自定义 `URLProtocol` 或本地模拟 HTTP/WebSocket 服务验证协议，不产生真实费用。
- 模拟断网、401、429、5xx、超时、空响应和取消。
- 模拟音频落盘成功但网络失败、转录成功但改写失败、文字完成但输入失败。
- 验证应用重启后中间状态恢复。

### 9.3 端到端与人工测试

macOS 系统权限和跨应用输入必须在真实机器人工验证。目标应用至少包括：

- 系统备忘录或文本编辑。
- 浏览器普通输入框和多行文本框。
- 主流聊天应用。
- 代码编辑器。
- 不支持辅助功能或安全输入的负向场景。

音频样本至少覆盖中文、英文、中英混合、短句、长段落、静音和背景噪声。

### 9.4 回归门禁

每个合并请求必须通过：

- Swift 格式检查。
- SwiftLint 或等价静态检查，新增警告视为错误。
- Swift Package 单元与集成测试。
- macOS App、SwiftUI Feature Model 和关键 View 测试。
- 数据库迁移测试。
- 生产构建。

涉及录音、快捷键、权限、文字注入或打包的变更，还必须附真实 macOS 验证记录。

## 10. 错误恢复场景

| 场景 | 预期行为 |
|---|---|
| 无麦克风权限 | 不开始录音，展示打开系统设置的操作 |
| 辅助功能未授权 | 可录音、转录和保存；自动输入失败但可复制 |
| 录音设备断开 | 安全关闭已录内容，标记录音失败或保存可用片段 |
| 数据库写入失败 | 立即停止继续处理，保留已产生文件并记录可恢复错误 |
| 断网或服务超时 | 保留录音，标记转录失败并允许重试 |
| 改写服务失败 | 保留原始文字，允许复制和仅重试改写 |
| 当前输入框消失 | 保留最终文字，提示复制或手动重新输入 |
| 应用异常退出 | 下次启动扫描中间状态和录音文件，不自动重复输入 |
| 磁盘空间不足 | 尽早阻止新录音并提示清理；不得生成看似成功的空文件 |

## 11. 构建与发布

第一版归档仅包含 Apple Silicon 架构：

```text
arm64
```

发布流程：

1. 从干净检出安装锁定依赖。
2. 运行全部静态检查、测试和迁移测试。
3. 使用 `xcodebuild archive` 生成 Release Archive，并导出生产 `.app`。
4. 检查架构、Bundle ID、版本、权限描述和图标。
5. 使用 Developer ID 签名。
6. 提交 Apple 公证并装订票据。
7. 生成签名 DMG。
8. 在一台未安装开发工具的 Apple Silicon Mac 上安装验证。
9. 验证首次权限、覆盖升级、历史数据保留和卸载后数据目录策略。
10. 记录文件校验值和发布说明。

开发阶段可使用临时签名，但正式分发不得让用户依赖绕过 Gatekeeper 的命令。

版本升级必须先验证数据库迁移。应用二进制卸载默认不自动删除用户数据；如未来提供彻底卸载工具，必须明确列出将删除的目录并二次确认。

## 12. 隐私和安全基线

已知风险：SQLite 中的 API 密钥为明文。第一版接受该风险，但必须在设置和文档中说明。

最低基线：

- 数据和录音目录仅当前用户可访问。
- SwiftUI 界面和可观察模型不获得完整密钥。
- 日志、错误、遥测和导出不包含密钥。
- 不加入任何遥测、崩溃云上传、广告或会员 SDK。
- 仅向用户选定的模型供应商发送必要的音频或文字。
- 设置页展示当前服务地址，让用户知道数据发送目的地。
- 自定义 HTTP 地址默认仅允许 HTTPS；回环地址可允许 HTTP。

后续安全版本可以通过本地主密码和数据库字段加密升级，数据访问层应预留密钥字段编码版本，但首版不实现。

## 13. 首版整体验收标准

### 核心流程

- 在任意普通文本输入框中，按一次快捷键开始、再按一次结束，最终文字自动出现。
- 中文、英文和中英混合均可完成录音、转录、改写和输入。
- 不启用改写时，原始转录作为最终文字。
- 快捷键冲突、重复触发和快速连按不会产生并发录音。

### 数据可靠性

- 每次录音在发起网络请求前已成为可播放本地文件。
- 成功和失败录音均永久保存，重启和应用升级后仍存在。
- 转录失败可用原录音重试；改写失败可仅重新改写。
- 强制结束应用不会导致已有有效录音消失。
- 删除操作同时处理记录和录音，失败时留下可恢复状态。

### 页面功能

- 首页准确显示今日、本周和总口述量。
- 历史支持任意日期范围、状态、收藏和文字搜索。
- 每条记录可复制文字、下载录音、收藏、删除；失败记录显示阶段和重试操作。
- 词典可添加单个词语、搜索、去重和删除。
- 设置可管理语音与改写配置、密钥、模型、地址、快捷键和麦克风。

### 协议

- OpenAI 兼容音频转录完整可用。
- OpenAI 兼容与 Anthropic 文字改写完整可用。
- 千问可通过 OpenAI 兼容预设配置；豆包和千问原生适配具有清晰扩展点。
- 401、429、超时、断网和坏响应均产生明确、脱敏、可恢复错误。

### 安装与运行

- DMG 可在 Apple Silicon macOS 安装到“应用程序”。
- 首次启动正确引导麦克风和辅助功能权限。
- 正式包通过签名、公证和 Gatekeeper 验证。
- 无网络时仍可浏览、搜索、复制、下载和删除本地历史。

## 14. Kimi 开发完成后的强制审查流程

开发完成不等于可以发布。必须由独立审查 Agent 依次执行：

1. 对照任务清单和本文件逐条检查功能缺失。
2. 审查 Swift Package 依赖边界，重点寻找巨大 AppModel、供应商逻辑泄漏和 SwiftUI View 直接持久化。
3. 审查录音文件可靠性、状态机合法性、数据库事务和异常恢复。
4. 搜索密钥、鉴权头、口述文字进入日志或 SwiftUI 可观察状态的风险。
5. 运行格式、静态检查、单元、集成、迁移和生产构建。
6. 在真实 Apple Silicon Mac 完成功能验收和权限测试。
7. 注入断网、限流、超时、崩溃、磁盘不足和输入失败。
8. 将问题按阻断、严重、一般和建议分级。
9. 由 Kimi 修复阻断和严重问题，并补充对应回归测试。
10. 独立审查 Agent 重新验证修复，不接受只凭文字说明关闭问题。

必须由 Kimi 修复的情况包括：数据或录音丢失、状态无法恢复、重复输入、密钥泄露、权限崩溃、数据库迁移失败、核心协议不可用、生产构建失败，以及主要页面功能缺失。一般视觉微调可在核心验收通过后处理。
