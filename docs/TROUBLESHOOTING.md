# VoiceCore 故障排查

> 版本：v0.9 草案（随真机验收 TEST-004/REL-002 补充实测案例）

按症状查找。所有日志位于数据目录的 `logs/` 子目录（路径见 `docs/DATA_LOCATIONS.md`），日志不包含完整密钥与完整口述文字。

## 1. 无法录音

| 症状 | 排查 |
| --- | --- |
| 提示没有麦克风权限 | 系统设置 → 隐私与安全性 → 麦克风 → 打开 VoiceCore；授权后重试 |
| 快捷键无反应 | 确认菜单栏有 VoiceCore 图标；检查快捷键是否与系统/其他应用冲突，在「设置 → 通用」更换快捷键 |
| 开始录音即报错 | 检查输入设备：系统设置 → 声音 → 输入，确认所选麦克风可用；插拔设备后重试 |
| 提示磁盘写入失败 | 检查磁盘剩余空间；确认数据目录权限未被修改（应为仅当前用户可读写） |

## 2. 识别或改写失败

| 症状 | 排查 |
| --- | --- |
| 「识别失败」，录音还在 | 录音与原文不会丢失。检查网络后，在历史中对该条点「重新识别」 |
| 提示认证失败 | 「设置 → 模型」中检查 API 密钥是否过期/填错；密钥以掩码显示，重新输入会覆盖，留空则保留原值 |
| 提示限流 | 服务方限制，稍后在历史中重试即可（应用对限流只自动重试一次） |
| 提示超时 | 增大该模型配置的超时时间；长录音建议更大超时 |
| 「改写失败」 | 点「仅重新改写」，不会重复消耗语音识别额度 |
| 测试连接成功但实际识别失败 | 确认配置已「设为默认」；核对模型名是否为音频模型（如 `whisper-1`）而非文本模型 |

## 3. 自动输入失败

| 症状 | 排查 |
| --- | --- |
| 提示需要辅助功能权限 | 系统设置 → 隐私与安全性 → 辅助功能 → 打开 VoiceCore |
| 文字没有出现在输入框 | 部分场景（密码框、安全输入、部分终端）系统禁止辅助输入——这是系统安全行为，文字已保存在历史中，手动复制即可 |
| 输入后剪贴板内容变了 | 自动输入通过剪贴板中转，应用会在粘贴后恢复原剪贴板；若目标是安全输入场景被中断，剪贴板里可能仍是识别文字 |
| 某个应用里总是失败 | 在历史中对该条点「再次输入」；仍失败请把「应用名＋场景＋日志时间」反馈给开发者 |

## 4. 历史与数据

| 症状 | 排查 |
| --- | --- |
| 应用异常退出后录音不见了 | 重新启动应用：启动恢复会把未完成录音标记为「录音失败/可重试」，已落盘音频保留，可在历史中重试 |
| 想确认录音文件是否还在 | 打开数据目录的 `recordings/` 子目录按日期查找 `.m4a` 文件 |
| 导出历史里没有密钥 | 这是设计：普通导出不包含模型配置与密钥 |
| 删除后还能恢复吗 | 不能。删除会同时移除数据库记录与录音文件，需二次确认 |

## 5. 界面与显示

| 症状 | 排查 |
| --- | --- |
| 主窗口关掉了找不到 | 点菜单栏图标 →「打开主窗口」 |
| 界面文字显示不全 | 窗口可拖拽放大，最小尺寸为 860×560 |
| 旧系统看不到玻璃效果 | 属正常降级：macOS 26 以下使用系统材质代替 Liquid Glass，功能完全一致 |

## 6. 仍然无法解决

向开发者反馈时请附上：

1. macOS 版本与 Mac 型号（ → 关于本机）。
2. 应用版本与复现步骤。
3. `logs/` 目录中对应时间段的日志文件（不含密钥，可放心提供）。
