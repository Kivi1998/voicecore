# 模型提供商协议与适配规范

## 1. 目标

模型调用必须通过协议适配层，口述编排器不得引用厂商名称、请求字段或鉴权细节。

第一版范围：

- 语音识别：必须完整实现 OpenAI 音频转录协议。
- 千问：可通过 OpenAI 兼容配置使用；保留千问原生实时协议适配位置。
- 豆包：保留原生协议适配位置，可作为首版增强项，不影响通用流程交付。
- 文字改写：完整实现 OpenAI 兼容聊天协议与 Anthropic Messages 协议。
- 所有服务均使用用户自备地址、模型名称和密钥，不提供内置额度。

## 2. 统一能力模型

所有适配器位于 `VoiceCoreProviders` Swift Package，通过依赖注入获得独立配置的 `URLSession`、时钟和日志接口。生产会话使用临时请求所需的缓存和凭据策略，不依赖全局 `URLSession.shared`。网络类型、HTTP 头和厂商响应只存在于适配器内部。

### 2.1 语音识别接口

概念接口：

```swift
public protocol SpeechProvider: Sendable {
    var capabilities: SpeechCapabilities { get }
    func validate() async throws -> ValidationResult
    func transcribe(_ request: SpeechRequest) async throws -> SpeechResult
}
```

`SpeechRequest` 至少包括：

- 本地音频文件引用。
- MIME 类型和时长。
- 可选语言提示；首版允许自动、中、英。
- 词典词语列表。
- 超时和取消信号。
- 记录和尝试标识，仅用于本地日志关联。

`SpeechResult` 至少包括：

- 原始转录文字。
- 可选识别语言。
- 可选供应商请求标识。
- 可选音频时长和用量元数据。

`SpeechCapabilities` 声明是否支持文件上传、流式音频、语言提示、热词和时间戳。业务层只能根据能力调用，不能根据厂商名称分支。

### 2.2 文字改写接口

```swift
public protocol RewriteProvider: Sendable {
    var capabilities: RewriteCapabilities { get }
    func validate() async throws -> ValidationResult
    func rewrite(_ request: RewriteRequest) async throws -> RewriteResult
}
```

`RewriteRequest` 包括：原始文字、词典、界面语言、用户提示词、最大输出长度、超时和取消信号。

`RewriteResult` 包括：最终文字、供应商请求标识、可选 token 用量和完成原因。

## 3. OpenAI 音频转录协议

### 3.1 配置

用户可配置：

- 配置名称。
- 基础地址或完整转录地址。
- API 密钥。
- 模型名称。
- 默认语言：自动、中文、英文。
- 超时时间。
- 自定义请求头。
- 额外参数白名单。

默认端点按基础地址拼接 `/v1/audio/transcriptions`。如果用户填写完整端点，则不得重复拼接。URL 拼接必须处理末尾斜杠。

### 3.2 请求

使用 URLSession 构建 `multipart/form-data` 上传任务，核心字段：

- `file`：音频文件。
- `model`：模型名称。
- `language`：可选。
- `prompt`：供应商支持时，将有限长度词典作为提示传入。
- `response_format`：优先请求结构化 JSON；不兼容时允许配置简化格式。

鉴权默认使用：

```text
Authorization: Bearer <api-key>
```

自定义请求头可以覆盖非安全默认值，但不得通过普通日志输出。禁止用户自定义 `Content-Length`、multipart 边界等由客户端维护的头。

### 3.3 兼容性策略

“OpenAI 兼容”并不代表所有供应商完整一致。适配器应：

- 接受标准 `{ "text": "..." }` 响应。
- 对缺少 `text`、空文字、非 JSON 成功响应给出明确错误。
- 允许预设提供默认地址、模型示例和字段能力，但预设最终仍生成普通配置。
- 额外参数只允许通过受控 JSON 白名单传递，避免覆盖核心字段。
- 保存脱敏配置快照，便于历史记录说明使用的服务。

千问支持 OpenAI 兼容音频转录时，应优先复用本协议，只提供“千问”配置预设，不重复实现相同 HTTP 流程。

## 4. 千问原生扩展

千问原生适配器用于未来的实时 WebSocket、专有热词或其他 OpenAI 兼容协议无法表达的能力。

实现要求：

- 位于 `VoiceCoreProviders` 中的独立 `QwenSpeechProvider` target 或目录，实现同一 `SpeechProvider` 协议。
- 专有配置存入类型化结构，再序列化至配置扩展字段。
- 将实时部分结果保留在会话内存或临时事件中，只有最终结果写入 `raw_transcript`。
- `URLSessionWebSocketTask` 断开后先确保本地录音完成，再将记录标为可重试；不得因流式会话失败删除音频。
- 不能让实时协议改变历史、重试、改写或输入模块。

首版如果不实现原生千问，设置页必须明确显示千问可通过 OpenAI 兼容方式配置，不能展示不可工作的选项。

## 5. 豆包原生扩展

豆包语音通常需要火山引擎专有鉴权、资源标识和 WebSocket 数据帧，因此作为独立适配器。

配置可能包括：

- 应用或项目标识。
- API 密钥或访问令牌。
- 资源编号。
- WebSocket 地址。
- 语言、标点、热词等选项。

实现要求：

- 协议编码、压缩、序列号和错误码解析全部封装在 `DoubaoSpeechProvider` 内。
- 录音仍由统一音频模块负责；适配器只消费标准音频帧或已保存文件。
- 同时流式发送和本地写盘，本地写盘失败必须停止会话，不能继续产生不可恢复的云端结果。
- 停止录音后等待最终结果应有独立短超时，超时则保留音频并允许文件方式或同协议重试。
- 将豆包错误码映射为统一错误类别。

## 6. OpenAI 兼容文字改写协议

默认使用 Chat Completions 风格接口：

```text
POST /v1/chat/completions
Authorization: Bearer <api-key>
Content-Type: application/json
```

请求包含系统指令和用户内容。第一版不要求流式输出，避免增加状态复杂度。响应解析最终文本，不向领域层暴露 `choices` 等供应商结构。

支持的配置：

- 基础地址或完整地址。
- 模型名称。
- API 密钥。
- 温度等少量白名单参数。
- 最大输出长度。
- 超时。
- 自定义请求头。

预设可覆盖 OpenAI、DeepSeek、千问、豆包文字模型及其他兼容服务，但都走同一适配器。

## 7. Anthropic Messages 协议

默认端点：

```text
POST /v1/messages
x-api-key: <api-key>
anthropic-version: <configured-or-supported-default>
Content-Type: application/json
```

系统提示使用协议的 `system` 字段，原始转录放入用户消息。解析文本内容块并按顺序拼接，忽略未知但合法的非文本块；完全没有文本块时返回标准坏响应错误。

兼容代理可能使用不同鉴权头或基础地址，因此允许受控自定义请求头。`anthropic-version` 必须有明确默认值并可配置，不能散落在业务代码中。

## 8. 改写提示词规范

默认提示词目标是忠实整理，而非回答用户：

- 删除无意义口头语和明显重复。
- 修正标点、段落和中英文空格。
- 保持原意、事实、数字、专有名词和语气。
- 中英混合内容不得强制翻译。
- 根据词典修正专有名词。
- 只输出整理后的文字，不解释处理过程。
- 信息不确定时保留原表达，不得补充事实。

提示词由版本化内置模板、词典和用户可选附加指令组成。历史记录保存脱敏的提示词版本标识，不必保存整段系统提示。

必须防止用户口述中的“忽略以上指令”等内容被当作系统控制；原始文字放在清晰的数据边界中，并明确要求模型只执行整理任务。

## 9. 配置验证和测试连接

保存配置时只进行格式验证，不应在未获得用户操作时自动发送音频或文字。设置页的“测试连接”是显式操作：

- 语音配置使用应用自带的短小无敏感测试音频，或让用户选择测试文件。
- 改写配置使用固定无隐私短文本。
- 返回连接成功、鉴权失败、模型不存在、限流、地址错误或超时。
- 测试结果不得记录密钥和完整响应正文。

保存新密钥时，空值表示保持原密钥，显式“清除密钥”使用独立操作，避免遮罩文本被错误保存为真实密钥。

## 10. 标准错误映射

| 情况 | 标准错误 | 是否可重试 |
|---|---|---|
| 401/403 | `authentication_failed` | 修改配置后可重试 |
| 429 | `rate_limited` | 可延迟重试 |
| DNS、断网 | `network_unavailable` | 可重试 |
| 客户端超时 | `provider_timeout` | 可重试 |
| 模型不存在、参数错误 | `provider_rejected` | 修改配置后可重试 |
| 2xx 但结构无法解析 | `provider_bad_response` | 可重试并记录脱敏摘要 |
| 用户取消 | 独立取消结果 | 不显示为服务故障 |

自动重试只适用于短暂网络错误和部分 5xx，最多少量次数，并使用带抖动的指数退避。用户主动点击重试不受自动次数替代。音频转录请求是否可自动重发必须考虑供应商计费；默认只自动重试连接建立失败，不自动重复已经可能被服务端处理的请求。

## 11. 超时与取消

- 连接超时、首字节超时和总请求超时分别配置合理默认值。
- 用户删除记录或退出应用时可以取消网络任务，但不能删除已经保存的录音。
- 用户再次点击重试前，必须确认同阶段没有仍在运行的请求。
- 长音频允许更长总超时，不能对所有时长使用同一个极短值。
- 超时后保留供应商请求标识和尝试记录，不保留敏感响应。
- Swift `Task` 取消必须传播到对应 `URLSessionTask` 或 `URLSessionWebSocketTask`；适配器把 `CancellationError` 作为取消结果，而不是供应商故障。
- 响应数据设置明确上限；流式下载或上传不能无界累积到内存。

## 12. 协议测试策略

每个适配器必须具备：

- 请求构造单元测试。
- URL 拼接和自定义头测试。
- 标准、空、异常响应解析测试。
- HTTP 状态和供应商错误映射测试。
- 密钥、鉴权头和文本不进入日志的测试。
- 使用本地模拟服务器的契约测试，不依赖真实计费服务。
- 至少一个由开发者手动触发、使用环境变量密钥的真实服务冒烟测试；默认测试命令不能产生费用。

音频测试样本必须短小、拥有合法使用权，并包含中文、英文和中英混合三组。预期结果允许做归一化匹配，不应要求不同模型逐字完全一致。

## 13. 协议验收标准

- OpenAI 兼容语音配置可以使用自定义基础地址、模型和密钥完成文件转录。
- 千问可通过 OpenAI 兼容预设完成转录；未实现原生协议时不会出现误导入口。
- OpenAI 和 Anthropic 改写适配器对同一输入均返回统一 `RewriteResult`。
- 切换配置后无需重启应用，新会话使用新配置，历史保留脱敏旧配置快照。
- 中文、英文和中英混合录音均能经过完整流程。
- 401、429、超时、断网、空响应均映射为用户可理解且可重试的状态。
- 任何协议失败都不会删除或覆盖本地录音。
- 日志、SwiftUI 状态流和历史快照中均不存在完整 API 密钥。
